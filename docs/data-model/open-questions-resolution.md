# Resolution of the 27 M0.2 open questions

Source: [`../architecture/open-questions-m0.3.md`](../architecture/open-questions-m0.3.md). **Status:** `Resolved` (decided; implemented or fixed by ADR), `Deferred` (consciously postponed, with blocker and target milestone), `Superseded` (replaced by a different decision).

**Result: 25 Resolved · 1 Deferred · 1 Superseded = 27.** Nothing disappeared silently.

| # | Question | Decision | Status | ADR / document | Reason |
| --- | --- | --- | --- | --- | --- |
| 1 | Primary-key strategy | UUIDv7 on every surrogate-key table, DB default `uuidv7()`; natural `code` keys for reference tables; composite keys for attribute-less link tables; no separate public id | Resolved | [0007](../decisions/0007-primary-keys-uuidv7.md) | portability for exports/packs, index locality, PG18 + Laravel native, one id per row |
| 2 | Soft deletes vs hard delete vs archival | No Laravel soft deletes. Canonical: `retired_at`; knowledge: versioned; personal: hard delete; external id mappings: retire; audit: retention | Resolved | [0008](../decisions/0008-storage-conventions.md), [indexes](indexes-and-constraints.md#delete-policy) | providers withdraw data without TrophyVault losing it; privacy deletes must be real |
| 3 | Versioning/history storage | Guide-level immutable `guide_versions`; objectives carry introduced/retired version; trophy timelines derived from `earned_at`; `ProgressSnapshot` table deferred until a feature needs non-derivable history; no event sourcing | Resolved (snapshot table planned-deferred, no open decision) | [0012](../decisions/0012-account-owned-progress.md), [0013](../decisions/0013-objectives-trackers-guides.md) | history is mostly derivable; avoid speculative tables |
| 4 | Enum vs lookup vs CHECK | Closed code-known sets: CHECK + PHP enum (test-synchronised); data-extensible vocabularies: lookup tables; no native PG enums | Resolved | [0008](../decisions/0008-storage-conventions.md) | cheap evolution, no invalid strings, migration-friendly |
| 5 | JSONB scope | JSONB only for rarely-queried provider/type-specific data, versioned inputs, bounded payloads; never for relations/ids/progress/secrets; NOT NULL `'{}'` + shared `jsonb_is_safe_object()` CHECK (object, ≤ 64 KiB, no credential-looking key at any depth) | Resolved | [0008](../decisions/0008-storage-conventions.md) | keeps the relational core relational |
| 6 | Objective tree storage; sibling ordering | Adjacency list + recursive CTE; composite FK keeps parent in same guide; `position` with deferrable `UNIQUE NULLS NOT DISTINCT`; cycle trigger | Resolved (table arrives M4) | [0013](../decisions/0013-objectives-trackers-guides.md) | simplest robust option for small/medium trees |
| 7 | Indexing/constraints; external-id uniqueness | Query-pattern-driven indexes; named constraints; active `(provider, namespace, value)` unique | Resolved | [indexes-and-constraints](indexes-and-constraints.md), [0009](../decisions/0009-external-identifiers.md) | integrity in the database; no blanket indexes |
| 8 | Models in `app/Models` or `app/Domain`; Eloquent in domain code | Eloquent models in `app/Models/<Domain>/`; services/value objects in `app/Domain/<Domain>/` when they exist; Eloquent used directly, no repositories | Resolved | [conventions](conventions.md#code-placement-adr-0008-q8) | Laravel conventions, factories resolve automatically, no enterprise layering |
| 9 | Release ↔ platform/region/edition cardinality | Release n:m platforms; exactly one region (`unknown`/`global` real values); optional edition of the same game | Resolved | [0011](../decisions/0011-catalog-and-trophy-structure.md) | cross-gen releases exist; region NULL would hide "unknown" |
| 10 | TrophySet ↔ Game/GameRelease | Set belongs to exactly one game; n:m to releases via same-game-guaranteed link table; n:m to platforms | Resolved | [0011](../decisions/0011-catalog-and-trophy-structure.md) | covers stacks, shared sets and cross-platform cases without artificial 1:1 |
| 11 | Storage of relations | One table per concept; directed vs ordered-pair symmetric kinds; no stored inverses; pair-unique and autopop-exclusive rules | Resolved | [0011](../decisions/0011-catalog-and-trophy-structure.md) | real FKs, no contradictory rows |
| 12 | Where group classification lives | `classification` + `classification_origin` columns on `trophy_groups`, separate from structure; `unknown` default | Resolved | [0011](../decisions/0011-catalog-and-trophy-structure.md) | provider structure ≠ TrophyVault semantics; manual overrides survive imports |
| 13 | Trophy identity across provider updates | `(trophy_set_id, set_key)`; upsert by key; never delete on upstream removal (warn) | Resolved | [0011](../decisions/0011-catalog-and-trophy-structure.md) | stable earned rows; `retired_at` only if real data demands |
| 14 | Where provenance lives | Cross-cutting `sources` + `provenance` pointing at subjects; subjects hold no provenance FK | Resolved (tables M2) | [0010](../decisions/0010-provenance-and-sync-model.md) | fixes the canonical→knowledge dependency problem |
| 15 | ExternalRecord / ExternalIdentifier / normalised rows; payload retention | Identifier = id mapping; external record = observed provider record with hash and bounded payload; provenance links rows to records; retention by job (hash kept, payload purged) | Resolved (tables M2) | [0009](../decisions/0009-external-identifiers.md), [0010](../decisions/0010-provenance-and-sync-model.md) | clear separation of identity, observation, derivation |
| 16 | Conflict resolution between providers | Principle recorded (manual > platform > third-party > community, visible via provenance); **mechanism not decided** | **Deferred** → M2/M3 | [0010](../decisions/0010-provenance-and-sync-model.md) | blocked by lack of real multi-provider data; deciding now would be guessing |
| 17 | Where adapters live | `app/Integrations/<Provider>/` for adapters/DTOs; contracts and normalisation in `app/Domain/Sync/`; domain never imports integrations | Resolved | [0010](../decisions/0010-provenance-and-sync-model.md) | enforces the provider boundary in the code layout |
| 18 | Earned trophies: User vs PsnAccount | Hang on the PSN account (`psn_account_trophy_sets`, `psn_account_trophies`); personal non-PSN data on the user | Resolved | [0012](../decisions/0012-account-owned-progress.md) | origin/authority, several accounts, clean unlink |
| 19 | Single- vs multi-user | Schema multi-user capable (all personal data owner-keyed); first release may run single-user; auth decided separately | Resolved | [0012](../decisions/0012-account-owned-progress.md) | no schema rework later; M1 stays simple |
